## Architecture Summary (only what affects new work)

- Every change AA makes is a **tool call** (`lib/assistant/tools/*`):
  parse → validate (fresh state, R16) → preview → run, executed by
  `ToolExecutor` with a ledger row and an `UndoRecipe` in one transaction.
  A screen tap uses `runDirectAction` or the executor with a shared
  `groupId`, so one UNDO reverses a group. New writing tools need a round
  trip in `test/assistant/tools_undo_test.dart` (a guard test enforces it).
- Proactive work: pure scanners (`lib/domain/assistant/scanners.dart`) →
  `ScannerRunner` → proposals (Inbox), or direct execution under HANDS-OFF
  via `decide()`; keys are never re-proposed (`knownProposalKeys`).
- Pure domain modules with fixed-clock tests: `briefing.dart`,
  `day_planner.dart`, `voice_state.dart`, `scanners.dart`, `quick_parse.dart`.
- Wording lives in l10n extensions (`lib/l10n/action_text.dart`,
  `features/briefing/view/briefing_text.dart`, `voice_controller.dart#spokenReply`).
- Android specifics (permissions, `<queries>`, receivers, the Kotlin QS tile,
  shortcuts) are generated by `tool/ci/android_patches.dart` with tests.

## Rules (from CLAUDE.md; enforced by tests in `test/code_rules/`)

- R1 enums stored by index are append-only. R2 every schema change = migration + migration test; after a bump run `dart run drift_dev make-migrations` and commit `drift_schemas/` + `test/drift/`.
- R7/R8 no `DateTime.now()` / `Duration(days:)` in `lib/` (use `clock`, `addDays`, `today()`).
- R11 action notifiers using `ref` after `await` are keepAlive. R12 writes via `runAction`. R14 `ErrorView`, never raw errors.
- `lib/domain/` imports no Flutter/Drift/Riverpod and returns no English.
- No string literals in widgets: ARB (`lib/l10n/app_en.arb`) + `context.l10n`; times/dates via `lib/l10n/formats.dart`. No typed capitals in strings.
- API keys only in `SecureKeyStore`.
- Golden change → `flutter test --update-goldens test/goldens`, **look at the images**, commit them.
